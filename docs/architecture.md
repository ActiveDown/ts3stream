# Архитектура TS3Stream

## Общая схема

```
TS3 client + plugin ──HTTPS/WSS──▶ Caddy ──▶ LiveKit (SFU) + control API
        │                              │
        └── WebRTC media (UDP/TCP) ────▶ LiveKit
```

Стоковый TS3-клиент и стоковый TS3-сервер не модифицируются.

## Компоненты

### Плагин TeamSpeak 3 (`plugin/`)

DLL для TS3 API 26, x64, Qt 5.15.2. Что делает:

- добавляет кнопку **Стрим** в тулбар;
- открывает диалог захвата: монитор/окно, звук, FPS;
- захватывает видео через Windows Graphics Capture;
- захватывает звук через WASAPI process loopback;
- публикует H.264 + Opus в LiveKit;
- рисует LIVE-бейджи и открывает viewer по трём путям (контекстное меню, кнопка в панели клиента, клик по LIVE);
- показывает панель просмотра и fullscreen с панелью участников.

Ключевые ограничения:

- плагин использует Qt DLL, которые уже загружены в TS3;
- указатели на виджеты TS3 хранятся в `QPointer`, чтобы teardown клиента не оставлял висячих ссылок;
- event filter ставится только на viewport дерева сервера (для клика по LIVE) и снимается при shutdown; на `MainWindow`/`InfoFrame` фильтры не ставятся;
- остановленные WGC/audio-объекты не разрушаются до выхода процесса: их destructor в момент завершения TS3 вызывал fail-fast в ucrtbase;
- LiveKit room при shutdown намеренно утекает, DLL плагина запинена.

### Control API (`service/`)

Go-бинарник. Отвечает за:

- выдачу JWT LiveKit (`/api/token`);
- реестр активных стримов (`/api/streams/start|heartbeat|stop|...`, `/api/live`);
- TTL 15 секунд; плагин обновляет запись каждые 5 секунд;
- опциональный общий ключ `X-TS3Stream-Key`.

Реестр нужен только для LIVE-бейджей и списка стримов. Медиа идёт напрямую через LiveKit.

### LiveKit

SFU: signaling, ICE, TURN, JWT, публикация/подписка. Одна комната на канал TS3:

```
ts3-<sha1(serverUid)[0:12]>-<channelId>
```

### Caddy

TLS-терминация: HTTPS для control API и WSS для LiveKit signaling. Медиа идёт по UDP/TCP напрямую в LiveKit.

## Поток запуска стрима

1. Пользователь подключается к TS3-серверу; кнопка «Стрим» становится активной.
2. Плагин проверяет, что стрим ещё не запущен.
3. Плагин вычисляет комнату по текущему серверу и каналу.
4. Control API выдаёт publish-JWT.
5. Плагин подключается к LiveKit и запускает WGC + audio helper.
6. После успешного старта захвата плагин отправляет `streams/start`.
7. Каждые 5 секунд повторяется идемпотентный `streams/start` (это же восстанавливает реестр после рестарта control API).
8. При остановке отправляется `streams/stop`.

## Поток просмотра

- Контекстное меню клиента: плагин получает clientID, вычисляет комнату по каналу клиента и запрашивает список стримов.
- Кнопка в панели клиента: ник выбранного клиента ищется в локальном кэше LIVE-стримов.
- Клик по LIVE-бейджу: всплывающее подтверждение, затем тот же путь.
- Control API выдаёт subscribe-JWT; viewer подключается к комнате и фильтрует видео по identity выбранного стримящего.

## Звук

- **Приложение**: `PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE` для PID окна.
- **Система**: `PROCESS_LOOPBACK_MODE_EXCLUDE_TARGET_PROCESS_TREE` для дерева процессов TS3.
- Сырой device loopback не используется.
- Helper проверяет число `ts3client_win64.exe` на старте и каждую секунду. Если процессов не ровно один, системный звук отключается (fail closed). Если enumeration завершилась ошибкой — тоже отключается.

## Fullscreen

- Панель становится top-level окном и получает screen по глобальной позиции окна TS3.
- Флаг `fullscreen_` выставляется до `showFullScreen`, иначе 100-мс watchdog успевает вернуть панель в InfoFrame.
- Панель участников — дочерний виджет с полупрозрачным фоном; кнопки «Скрыть»/«Выйти» крупные, с контрастным фоном.
- Esc выходит, F11 переключает.

## Сборка и установка

- `plugin/build.ps1` собирает DLL и helper, копирует их в `%APPDATA%` для отладки.
- `tools/package.ps1` собирает `.ts3_plugin` с `package.ini`, DLL, helper и LiveKit DLL.
- `ensureRuntimeDlls` при первом запуске копирует LiveKit DLL из пакета в каталог данных TS3; при обновлении перезаписывает более новые файлы.
- Helper ищется сначала рядом с плагином (пакет), затем в `%APPDATA%` (ручная установка).
